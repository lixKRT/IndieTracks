# IndieTracks 信息管理系统开发设计文档

> 创建：2026-06-09

## 一、系统概述

IndieTracks 信息管理系统（Admin CMS）是面向 Pro（社团成员）和 Staff（管理员）的后台管理平台，用于管理专辑、社团、用户、标签、评论等数据，并提供数据可视化透视页。

### 1.1 访问权限

| 角色 | 登录权限 | 可见菜单 |
|:---|:---|:---|
| `normal` | ❌ 不可访问 | 无 |
| `pro` | ✅ 可访问 | 数据透视、所属社团专辑管理、标签管理、评论管理 |
| `staff` | ✅ 可访问 | 全部菜单 |

### 1.2 技术栈

- **前端**：Vue 3 + Vue Router + Pinia（复用现有技术栈）
- **后端**：Spring Boot + MyBatis-Plus（复用现有架构）
- **认证**：JWT + Cookie（复用现有认证系统）
- **样式**：暗色主题（复用 tokens.css）

## 二、权限模型

### 2.1 角色定义

| 角色 | 说明 | 权限范围 |
|:---|:---|:---|
| `normal` | 普通用户 | 仅前台浏览、收藏、购买、评论 |
| `pro` | 社团成员 | 前台 + 管理所属社团的专辑/标签/评论 |
| `staff` | 管理员 | 前台 + 全部后台管理权限 |

### 2.2 Pro 用户权限明细

| 资源 | 查看 | 新增 | 编辑 | 删除 |
|:---|:---|:---|:---|:---|
| 所属社团专辑 | ✅ | ✅ | ✅ | ✅ |
| 所属社团专辑标签 | ✅ | ✅ | ✅ | ✅ |
| 所属社团专辑评论 | ✅ | — | — | ✅ |
| 非所属社团专辑 | ❌ | ❌ | ❌ | ❌ |
| 社团信息 | ✅ 只读 | ❌ | ❌ | ❌ |
| 社团成员 | ❌ | ❌ | ❌ | ❌ |
| 用户 | ❌ | ❌ | ❌ | ❌ |
| 标签（全局） | ✅ | ✅ | ✅ | ✅ |

### 2.3 Staff 用户权限明细

| 资源 | 查看 | 新增 | 编辑 | 删除 |
|:---|:---|:---|:---|:---|
| 专辑（全部） | ✅ | ✅ | ✅ | ✅ |
| 社团 | ✅ | ✅ | ✅ | ✅ |
| 社团成员 | ✅ | ✅ | ✅ | ✅ |
| 用户 | ✅ | ✅ | ✅ | ✅ |
| 标签 | ✅ | ✅ | ✅ | ✅ |
| 评论 | ✅ | — | — | ✅ |
| 曲目 | ✅ | ✅ | ✅ | ✅ |

### 2.4 权限实现方式

**后端：**
- `JwtAuthFilter` 从数据库查询 `user_role`，设置 Spring Security Authorities
- 使用 `@PreAuthorize` 注解进行方法级权限控制
- Pro 用户查询专辑时自动过滤为所属社团的专辑

**前端：**
- `/admin` 路由守卫检查用户角色
- 导航栏根据角色动态显示菜单
- Pro 用户只能看到所属社团的数据

## 三、页面设计

### 3.1 路由结构

| 路由 | 页面 | 权限 |
|:---|:---|:---|
| `/admin` | Dashboard 数据透视页 | pro, staff |
| `/admin/albums` | 专辑列表 | pro, staff |

| `/admin/circles` | 社团列表 | staff |
| `/admin/circles/:id` | 社团详情/成员管理 | staff |
| `/admin/users` | 用户列表 | staff |
| `/admin/tags` | 标签列表 | pro, staff |
| `/admin/comments` | 评论列表 | pro, staff |

### 3.3 页面详情

#### 3.3.1 Dashboard 数据透视页

**Staff 视角：**
- 用户统计：总数、本周/本月新增、注册趋势折线图、角色分布饼图
- 专辑统计：总数、免费/付费、本周/本月新增、发布趋势折线图、价格分布饼图
- 热门专辑 Top 50：按收藏数/评论数排序，支持本周/本月/全部切换
- 标签分布：标签云/柱状图
- 社团统计：总数、本周/本月新增、平均成员数
- 活跃社团 Top 50：按发布专辑数量排序，支持本周/本月/全部切换
- 社团成员分布：柱状图（1-5人、6-10人、10+）
- 评论/收藏统计

**Pro 视角：**
- 仅显示所属社团相关数据
- 专辑统计：所属社团专辑数量、发布趋势
- 热门专辑：所属社团内按收藏数/评论数排序
- 评论统计：所属社团专辑评论数

#### 3.3.2 专辑管理页

**列表页：**
- 表格展示：封面缩略图、标题、社团、价格、标签、发布时间、操作
- 筛选：社团、标签、价格区间、关键词搜索
- 分页：每页 20 条
- 操作：编辑、删除（批量删除）
- Pro 用户自动过滤为所属社团专辑

**新增/编辑页：**
- 基本信息：标题、封面上传、价格、所属社团（Pro 只能选所属社团）、发布日期
- 标签管理：添加/删除标签
- 曲目管理：
  - 曲目列表（可拖拽排序）
  - 上传音频文件（MP3/FLAC）
  - 在线播放审查
  - 下载音频文件
  - 编辑曲目信息（名称、时长）
  - 删除曲目

#### 3.3.3 社团管理页（Staff）

**列表页：**
- 表格展示：Logo、名称、成员数、专辑数、描述、操作
- 搜索：关键词搜索
- 操作：编辑、删除

**详情/成员管理页：**
- 社团信息编辑
- 成员列表：添加/移除成员

#### 3.3.4 用户管理页（Staff）

**列表页：**
- 表格展示：头像、用户名、邮箱、角色、注册时间、操作
- 筛选：角色、关键词搜索
- 操作：编辑角色、删除

#### 3.3.5 标签管理页

**列表页：**
- 表格展示：标签名、关联专辑数、操作
- 搜索：关键词搜索
- 操作：编辑、删除
- 新增标签

#### 3.3.6 评论管理页

**列表页：**
- 表格展示：用户、专辑、内容、时间、操作
- 筛选：专辑、用户、关键词搜索
- 操作：删除（Pro 只能删除所属社团专辑评论）

## 四、API 设计

### 6.2 权限控制

**方式一：SecurityConfig URL 级别**
```java
.requestMatchers("/api/admin/**").hasAnyAuthority("ROLE_staff", "ROLE_pro")
.requestMatchers("/api/admin/circles/**", "/api/admin/users/**").hasAuthority("ROLE_staff")
```

**方式二：@PreAuthorize 方法级别**
```java
@PreAuthorize("hasAuthority('ROLE_staff') or @albumSecurity.isOwner(#id, authentication)")
public ResponseEntity<?> updateAlbum(@PathVariable Integer id, ...) {
```

**推荐方式二**，因为 Pro 用户的权限需要动态判断（是否是所属社团的专辑）。

## 八、数据库变更

无需修改数据库结构。现有 14 张表已满足需求：
- `users` 表的 `user_role` 字段用于权限控制
- `user_circles` 表用于判断 Pro 用户所属社团
- `circles` 表的 `owner_user_id` 暂不使用
