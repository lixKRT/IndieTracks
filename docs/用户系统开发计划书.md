# IndieTracks 用户系统开发计划书

> 创建：2026-05-31 | grill-with-docs 访谈

## 一、功能范围

| 功能 | 说明 |
|------|------|
| 注册 | 用户名 + 邮箱 + 密码 |
| 登录 | 用户名或邮箱 + 密码，支持"记住我"（30天有效期） |
| 登出 | 清除 Cookie |
| 个人主页 | 头像、用户名、角色、注册时间 + 收藏专辑 + 关注社团 + 关注用户 |
| 收藏专辑 | 专辑详情页心形按钮，个人主页可取消 |
| 关注社团 | 社团详情页关注按钮，个人主页可取消 |
| 关注用户 | 用户主页关注按钮，个人主页可取消 |
| 发表评论 | 登录用户可发表评论 |
| 编辑评论 | 登录用户可编辑自己的评论 |
| 删除评论 | 登录用户可删除自己的评论 |

## 二、技术方案

### 2.1 认证方式

- **HttpOnly Cookie + JWT**
- Cookie 名称：`indietracks_token`
- 普通登录有效期：7 天
- "记住我"有效期：30 天
- Cookie 属性：`HttpOnly`、`SameSite=Lax`、`Path=/`

### 2.2 密码加密

- BCrypt（Spring Security 内置）

### 2.3 前端状态管理

- 新建 `useUserStore`（Pinia）
- 存储：当前用户信息、登录状态
- 刷新页面时从 `GET /api/auth/me` 恢复状态

## 三、接口设计

### 3.1 认证接口

| 方法 | 路径 | 说明 | 鉴权 |
|------|------|------|------|
| POST | `/api/auth/register` | 注册 | 无 |
| POST | `/api/auth/login` | 登录 | 无 |
| POST | `/api/auth/logout` | 登出 | 需登录 |
| GET | `/api/auth/me` | 获取当前用户信息 | 需登录 |

**注册请求体：**
```json
{
  "username": "string",
  "email": "string",
  "password": "string"
}
```

**登录请求体：**
```json
{
  "account": "string（用户名或邮箱）",
  "password": "string",
  "remember_me": false
}
```

**登录成功响应：**
```json
{
  "user_id": 1,
  "username": "xxx",
  "avatar_url": "xxx",
  "user_role": "normal"
}
```
（Token 通过 Set-Cookie 返回，不在 body 中）

## 四、数据库变更

现有表已满足大部分需求，需确认以下表结构：

```sql
-- 收藏表（已存在）
favorites(user_id, album_id, created_at)

-- 关注社团表（已存在）
circle_follows(user_id, circle_id, created_at)

-- 关注用户表（已存在，列名：user_id + followed_user_id）
user_follows(user_id, followed_user_id, created_at)

-- 评论表（已存在，按 comment_id DESC 排序，不显示日期）
comments(comment_id, album_id, user_id, content, created_at)
```

现有表结构满足需求，无需 DDL 迁移。

## 七、答辩要点

1. **Spring Security + JWT**：Filter 链、BCrypt 密码加密、HttpOnly Cookie 防 XSS
2. **RESTful 设计**：资源化 URL、HTTP 语义化（POST/PUT/DELETE）
3. **权限控制**：`@PreAuthorize` 注解、自定义鉴权逻辑
4. **前后端分离认证**：Cookie 传递 Token、前端 Pinia 状态管理
